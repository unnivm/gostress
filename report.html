Transport Errors Explained

Reference

Transport errors are network-level failures that occur before your application returns an HTTP response. Unlike HTTP failures (e.g. 500, 503), transport errors mean the request never reached the server or the response was never fully received. Common causes include:

deadline_exceeded — The request took longer than the allowed time. This usually means the server is overloaded, the database is slow, or there is a network bottleneck. Under high concurrency, this is often the first signal that your target is reaching capacity.

connection refused — The server actively rejected the TCP connection. This typically indicates the target service is down, not listening on the expected port, or has exhausted its connection pool.

connection reset — An established connection was abruptly terminated by the remote end. This can happen under heavy load when a server or load balancer drops connections to shed pressure.

EOF / broken pipe — The server closed the connection before sending a complete response. This often points to a crashed handler, a proxy timeout, or a server restart mid-request.
